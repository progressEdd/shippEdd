# Plan 03-02: Repo-relative paths in dispatch receipts and --status output (POL-02)

**Objective:** POL-02 lands on canonical master: every dispatcher that shares the receipt pattern (review, define, implement, wayfind) prints repo-relative paths — `.planning/runs/<id>.log` — in its dispatch receipt, its `--status` output, and (implement only) its duplicate-marker refusal, instead of machine-absolute ones. `dispatch-plan.sh` is assessed and unchanged: its printed paths (worktree, run dir) live under `$TMPDIR` outside the repo and have no repo-relative form; no SKILL.md example text needs edits (review's documented example `dispatched 01-verify (PID 1234) → .planning/runs/01-verify.log` already shows the target form, and implement's `$TMPDIR` examples remain accurate).

**cwd note:** your agent worktree is a fork of `master` — the skill scripts sit at the worktree root (`review/scripts/dispatch.sh`, …). All paths below are worktree-root-relative.

**Design (applies to all edits):** display paths are computed by stripping the `$root/` prefix: `runs_disp="${runs#"$root"/}"`. When the runs dir is under the repo root (the default `<state>/runs` case) this yields the repo-relative form (e.g. `.planning/runs`); when implement's dispatcher is pointed at a `$TMPDIR` run dir via `--state-dir`, the path is outside the repo and prints as-is — that is the only honest form for transient non-repo state, and it is what implement's SKILL.md documents.
