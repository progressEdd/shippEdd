Behavior contract: pre-check EVERY plan before the first merge (plan file, agent branch, target branch exists / has a checkout / checkout clean, fork base recorded) so a mid-sequence discovery can't strand plan k; then per plan, in command-line (plan) order: `merge-base(agent, target)` must equal the recorded fork base or DRIFT-halt naming the plan, branch, worktree path, recorded sha, and current merge-base; `git -C <target's checkout> merge --no-ff` (Decision 3: one merge bubble per plan) or CONFLICT-halt after `merge --abort`; then remove-then-delete cleanup (order matters: `git branch -d` refuses while the branch is checked out in a worktree).
```bash
#!/usr/bin/env bash
# shippEdd merge-back (EXEC-07). Orchestrator-owned, serialized merge of each
# plan's agent branch into its target branch, in the order given on the
# command line (plan order). Validates the recorded fork base before every
# merge — any drift (target or agent history moved since dispatch) halts that
# merge with a handoff naming every stranded artifact; nothing is silently
# resolved. Removes each plan's worktree and deletes its branch after a clean
# merge. Never touches STATE.md/ROADMAP.md — the gate's docs-side commit
# follows only after all merges succeed.
#
# Usage: merge-back.sh <state-dir> <NN> <slug> <plan-id> [<plan-id> ...]
set -euo pipefail

root="$(git rev-parse --show-toplevel 2>/dev/null || pwd)"
state="${1:?usage: merge-back.sh <state-dir> <NN> <slug> <plan-id>...}"
nn="${2:?NN required}"; slug="${3:?slug required}"; shift 3
[ $# -gt 0 ] || { echo "usage: merge-back.sh <state-dir> <NN> <slug> <plan-id>..." >&2; exit 1; }

checkout_of() {  # path of the worktree holding branch $1, or empty
  git worktree list --porcelain | awk -v want="refs/heads/$1" '
    /^worktree / { wt = substr($0, 10); bra = ""; det = 0 }
    /^detached/  { det = 1 }
    /^branch /   { bra = substr($0, 8) }
    bra == want && !det { print wt; exit }
  '
}
plan_of()   { printf '%s\n' "$root/$state/phases/$nn-$slug/$1-PLAN.md"; }
target_of() { local t; t="$(sed -n 's/^target:[[:space:]]*//p' "$(plan_of "$1")" | head -n1)"; printf '%s\n' "${t:-master}"; }
rundir_of() { printf '%s\n' "${TMPDIR:-/tmp}/shippEdd/$nn-$slug/$1"; }

# Pre-check every plan BEFORE the first merge: fail loud, fail early.
for id in "$@"; do
  [ -f "$(plan_of "$id")" ] || { echo "HALT: no plan file for $id: $(plan_of "$id")" >&2; exit 1; }
  target="$(target_of "$id")"; agent="agent/$id"; run_dir="$(rundir_of "$id")"
  git rev-parse --verify --quiet "refs/heads/$agent"  >/dev/null || { echo "HALT: $id has no agent branch '$agent'" >&2; exit 1; }
  git rev-parse --verify --quiet "refs/heads/$target" >/dev/null || { echo "HALT: $id target branch '$target' not found" >&2; exit 1; }
  wt="$(checkout_of "$target")"
  [ -n "$wt" ] || { echo "HALT: $id target '$target' is checked out nowhere — the merge needs its checkout" >&2; exit 1; }
  [ -z "$(git -C "$wt" status --porcelain 2>/dev/null)" ] || { echo "HALT: $id target checkout '$wt' is dirty — commit or stash it first" >&2; exit 1; }
  [ -f "$run_dir/fork-base" ] || { echo "HALT: $id fork base not recorded at $run_dir/fork-base (tmp wiped?); merge-base(agent,$target) = $(git merge-base "$agent" "$target" | cut -c1-7) — record it there to proceed" >&2; exit 1; }
  echo "precheck $id → $target (checkout ${wt#"$root"/})"
done

for id in "$@"; do
  target="$(target_of "$id")"; agent="agent/$id"; run_dir="$(rundir_of "$id")"
  wt="$(checkout_of "$target")"
  fork_base="$(cat "$run_dir/fork-base")"
  mb="$(git merge-base "$agent" "$target")"
  if [ "$mb" != "$fork_base" ]; then
    echo "DRIFT: plan $id stranded — branch $agent forked at $(git rev-parse --short "$fork_base"), but merge-base with $target is $(git rev-parse --short "$mb"); worktree $run_dir/worktree left in place. Recover: inspect $agent, then either re-record $run_dir/fork-base (if $target's advance is legitimate) or re-plan the slice." >&2
    exit 1
  fi
  if ! git -C "$wt" merge --no-ff --no-edit "$agent" -m "merge($id): plan $id into $target"; then
    git -C "$wt" merge --abort
    echo "CONFLICT: plan $id stranded — branch $agent, worktree $run_dir/worktree, target $target. Recover: merge $agent into $target by hand in $wt, or resolve the collision and re-dispatch." >&2
    exit 1
  fi
  if [ -d "$run_dir/worktree" ]; then
    git worktree remove "$run_dir/worktree" \
      || { echo "HALT: $id worktree $run_dir/worktree is not clean to remove — inspect it, remove it manually, then delete branch $agent" >&2; exit 1; }
  fi
  git worktree prune
  git branch -d "$agent" \
    || { echo "HALT: branch $agent could not be deleted after merge — inspect manually" >&2; exit 1; }
  echo "merged $id → $target ($(git rev-parse --short "$target")) · worktree removed · branch $agent deleted"
done
```

~~~~markdown
# shippEdd implement — dispatch the waves, merge the branches

You are the orchestrator for the execution half of the phase loop. You dispatch one detached executor per **plan** into its own agent worktree, and when a wave lands you merge each agent branch back into its target branch — serialized, in plan order, drift-checked, worktrees cleaned up. You never implement anything yourself and never wait on a running wave. Executors own git inside their worktrees; you own git everywhere else: merge-back and the docs-side commit. Nothing this skill runs writes per-run state into the repo — dispatch state (prompt, log, markers, fork base) is transient under `$TMPDIR`, and plan state is derived from artifacts.

`<state>` is the workflow state dir resolved in step 0; all other paths are relative to it or to the repo root. This skill is self-contained: its scripts (`scripts/state-dir.sh`, `scripts/dispatch.sh`, `scripts/dispatch-plan.sh`, `scripts/merge-back.sh`) live in this folder; phase templates live in the skill's own `bootstrap/templates/` (sibling of this skill's folder).

## Ground rules

1. **Orchestrate, don't labor** — executors implement in fresh, detached contexts, each inside its own worktree. Your session sees dispatch lines, run states, and merge lines — never implementation detail.
2. **Artifacts are truth** — plan `NN-YY` is **executed** iff `<state>/phases/<NN>-<slug>/NN-YY-SUMMARY.md` exists with `status: complete` in its frontmatter, and **landed** iff, in addition, its target branch's log carries a `merge(NN-YY):` merge commit. Transient run state in `$TMPDIR` is advisory (liveness, logs); when it is missing — wiped tmp, reboot — derive from artifacts, never treat missing transient state as failure. This skill is idempotent and may be re-run at any moment, mid-run, mid-wave, or between waves.
3. **Wave data is plan-time data** — `wave`, `depends_on`, and `target` were precomputed by the planner into each plan's frontmatter (a missing `target` means `master`). You read them as-is; you never recompute, re-derive, or second-guess them.
4. **Isolation by worktree** — every executor gets its own worktree forked from its plan's target-branch HEAD (fork base recorded at dispatch), so same-wave plans never share a working tree. Same-**target** plans in one wave are a planning defect: step 2's overlap check demotes them to sequential with a visible warning — never silently.
5. **Facts from disk, decisions to the user** — anything readable (summaries, run state, git log, STATE.md) is read, never asked about. Questions use exactly this format (identical to bootstrap's and define's):

   ```
   ❓ <question>
     ➡️ 1. <recommended answer>
       2. <option>
       3. <option>
   ```

6. **Recommend and stop** — nothing auto-fires. After dispatching you stop and tell the user how to come back; the skill ends by naming the next command (`/skill:review`). Never run it yourself.
~~~~

~~~~markdown
## Prerequisites

- A shippEdd state dir (`/skill:bootstrap`) with a phase that has approved plans (`/skill:define`).
- git identity configured (`user.name` / `user.email`) — executors and the gate commit with it.
- Every plan's `target` branch checked out in some worktree with a clean tree at merge time (the merge runs in that checkout; `merge-back.sh` pre-checks and halts loudly otherwise).

## Common questions

**Why do executors commit now?**
Each executor works in its own worktree — no shared index to race on. Per-task commits make the work atomic and resumable: a re-dispatched plan verifies and continues prior commits (idempotent by law), and the merge-back has a real branch to merge.

**Who merges?**
The orchestrator gate, never the executor. After a wave lands, `merge-back.sh` merges each agent branch into its target with `--no-ff` (one merge bubble per plan), validating the recorded fork base first — if the target or the agent branch moved since dispatch, that merge halts with a handoff naming the plan, branch, worktree, and SHAs. Docs-side commits (summaries, STATE.md, ROADMAP plan ticks) land only after all merges.

**What if two plans of a wave target the same branch?**
Each still runs isolated in its own worktree, but their merges would collide — so the wave is demoted to sequential dispatch with a visible warning, flagged as a planning defect. The planner puts same-target plans in different waves via `depends_on`.

**How do I check on a running wave?**
The dispatch line prints the run dir (`${TMPDIR:-/tmp}/shippEdd/<phase>/<plan>/`): `tail` the log there, or run `dispatch.sh --status --state-dir` against that dir. Finishers write their SUMMARY and flip their own marker — nothing needs babysitting.

**When do the commits appear?**
Continuously inside each executor's worktree; on the target branch at the gate, as serialized `--no-ff` merges in plan order. The planning-repo side (summaries, STATE/ROADMAP) commits once per wave, after the merges.

## It's working if

- Dispatching a plan creates nothing under `.planning/` — the run dir lives under `$TMPDIR` and its path is printed at dispatch.
- Each executed plan leaves exactly one durable artifact: `NN-YY-SUMMARY.md` with `status` / `duration` / `key-files` / `requirements-completed` / `key-decisions` / `deviations` frontmatter.
- `git log <target> --merges` shows one `merge(NN-YY):` bubble per landed plan, in plan order; the agent branches and worktrees are gone.
- Re-running `/skill:implement` at any moment is safe: landed plans are skipped, in-flight ones reported, interrupted ones surfaced with recovery choices.
- Nothing runs git on the target branches except the gate; executors never merge; nothing auto-runs `/skill:review`.
~~~~
